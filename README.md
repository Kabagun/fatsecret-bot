# fatsecret-bot

Telegram-бот для групп пользователей: синхронизирует рецепты между двумя FatSecret аккаунтами и копирует заполненный дневник питания сразу на выбранный диапазон дат.

## Что уже реализовано

- Два Telegram-пользователя:
  - если `TELEGRAM_ALLOWED_USER_IDS` задан, пускаются только эти id;
  - если не задан, первые два пользователя, вызвавшие `/start`, регистрируются автоматически.
- Группы рецептов:
  - пользователь создает группу или подключается по коду;
  - если пользователь уже в группе, бот показывает только его группу, участников и кнопку отключения;
  - создатель группы может переименовать группу;
  - группа ограничивает список рецептов, аккаунтов и синхронизацию.
- Два FatSecret аккаунта добавляются через Telegram-кнопку `Аккаунты`; логин/пароль проверяются перед сохранением, затем пользователь задает короткий ник для списков.
- FatSecret аккаунт удаляется выбором конкретного аккаунта из списка группы.
- Импорт cookbook только в активную группу и merge по нормализованному названию рецепта внутри этой группы.
- Просмотр общего списка `/recipes`.
- Поиск внутри списка рецептов.
- Обновление из FatSecret `/refresh`.
- Просмотр рецепта с ингредиентами.
- Синхронизация выбранного рецепта из выбранного FatSecret аккаунта во все подключенные аккаунты.
- Создание рецепта из списка строк вида `название масса_г` с предварительной валидацией ингредиентов.
- Удаление рецепта из FatSecret на всех привязанных аккаунтах.
- Batch-удаление нескольких рецептов из FatSecret.
- Копирование всего дневника еды с выбранного аккаунта и даты на оба аккаунта группы:
  - произвольный диапазон от 1 до 7 дней;
  - существующая еда не удаляется, новые записи добавляются;
  - исходная дата на исходном аккаунте автоматически исключается;
  - личные рецепты синхронизируются через recipe mappings;
  - личные продукты один раз клонируются на второй аккаунт и переиспользуются;
  - повтор одного и того же callback не добавляет еду второй раз.

Бот не создает и не редактирует рецепты вручную. Рецепт создается/редактируется в FatSecret, затем пользователь сам выбирает конкретный рецепт в боте и запускает синхронизацию.

Подключение второго аккаунта только загружает его cookbook в активную группу. Отсутствующие рецепты не создаются автоматически; создание на другом аккаунте происходит только после явной кнопки `Синхронизировать` в карточке выбранного рецепта.

## Важное ограничение MVP

Создание рецепта на втором аккаунте подтверждено live-capture: `RecipeActionAndroidPage.aspx` с `action=recipeinitialsave`, `prid=0`; ответ имеет формат `SUCCESS:<recipe_id>`. Затем бот переносит ингредиенты через `ingredientsave` и сохраняет метаданные через `recipesave`.

Синхронизация делает целевой рецепт точной копией источника: обновляет найденные ингредиенты через их `iid`, добавляет отсутствующие и удаляет лишние через восстановленный из APK action `ingredientdelete`. Личными считаются только продукты с серверным `isOwn=true`; они сначала клонируются в аккаунт-получатель через `saveregional`, после чего их account-specific id сохраняется в SQLite и переиспользуется. Если FatSecret не принимает любое из этих изменений, аккаунт получает результат `ERROR`, а не неполный `OK`.

Поля ингредиента из ответа FatSecret (`rid`, `portionid`, `portionamount`) используются для межаккаунтной синхронизации без пересчёта. Нормализация в граммы существует отдельно только для отображения в Telegram и локального поиска. Source `iid` никогда не переносится: для добавления используется `iid=0`, а для обновления — `iid` строки целевого рецепта. Exact-sync не подменяет отклонённый публичный продукт похожим результатом поиска; исключение — подтверждённый `isOwn=true` продукт, для которого создаётся account-specific копия.

Удаление рецепта восстановлено из APK: `RecipeActionAndroidPage.aspx` с `action=recipedelete`, `rid=<recipe id>`, `fl=5`. Успешное удаление снимает remote-привязку аккаунта; локальная карточка удаляется только когда рецепт удален на всех привязанных аккаунтах.

Каждый Android/app запрос с auth-ошибкой или redirect получает не более одного повтора после fresh login. Если синхронизация успела создать новый рецепт на целевом аккаунте, но перенос ингредиентов или метаданных завершился ошибкой, бот удаляет этот новый target; существующие рецепты rollback не затрагивает.

Полностью загруженный cookbook считается источником истины для remote-привязок: бот удаляет из SQLite отсутствующие mappings и локальную карточку, когда у нее не осталось ни одного live remote id. Перед созданием рецепта из списка названия повторно проверяются по свежему cookbook, поэтому удаленный рецепт не вызывает ложный duplicate prompt или лишний цифровой суффикс.

Для дневника используются Android-контракты `RecipeJournalDayAndroidPage.aspx` и `update-journal-entries`. Личные продукты читаются через `RecipeAndroidPage.aspx` и создаются на втором аккаунте через `RecipeCustomEntryActionAndroidPage.aspx` с `action=saveregional`. Общий для дневника и рецептов mapping хранится в SQLite, поэтому один и тот же продукт повторно не создаётся.

Копирование переносит только записи еды. Вода, упражнения, фотографии и заметки не копируются. Перед записью бот показывает источник, диапазон, количество строк и предупреждает, что существующие записи сохранятся.

## Установка

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполнить `.env`:

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_ALLOWED_USER_IDS` или оставить пустым для авто-регистрации первых двух пользователей
- при необходимости `FATSECRET_AUTHORIZATION` и `FATSECRET_C_DESC`

FatSecret логины/пароли вводятся в боте через `Аккаунты` и сохраняются в runtime SQLite. `.env` и runtime SQLite лежат вне git.

Подробная безопасная трассировка запросов и синхронизации пишется в `FATSECRET_BOT_LOG_PATH` (по умолчанию рядом с SQLite в `fatsecret_bot.log`). Файл ротируется ежедневно, а архивы старше `FATSECRET_BOT_LOG_RETENTION_DAYS` удаляются; значение по умолчанию — 10 дней. Лог содержит аккаунт, action, recipe/food/ingredient/portion ids, выбранные fallback-кандидаты, HTTP status/Location и rollback, но не содержит пароли, auth headers или session keys.

## Запуск

```powershell
.\.venv\Scripts\Activate.ps1
python run_bot.py
```

Или после установки пакета в editable-режиме:

```powershell
pip install -e .
fatsecret-bot
```

## Команды

- `/start` - зарегистрироваться/проверить доступ.
- `/refresh` - подтянуть cookbook из FatSecret аккаунтов активной группы и смержить список.
- `/recipes` - показать объединенный список рецептов.
- `/groups` - создать группу, подключиться по коду или отключиться от текущей группы.
- `/diary` - выбрать аккаунт-источник, исходную дату и диапазон копирования дневника.

В карточке рецепта есть кнопки:

- `Синхронизировать`
- `Удалить в FatSecret`
- `К списку`

После `/start` бот показывает постоянные кнопки:

- `Рецепты`
- `Меню / Дневник`
- `Аккаунты`
- `Группы`

В списке рецептов есть пагинация, поиск, создание из списка, подпись аккаунтов-владельцев и кнопка `Удалить несколько` для batch-удаления. Inline-кнопки `Обновить` в списке нет; обновление доступно через `/refresh`.

Формат создания из списка:

```text
Филе 100
Теос греческий 200
Масло 6
```

Бот считает последнее число граммами, подбирает часто использованные ингредиенты из рецептов группы, затем ищет в FatSecret и показывает итоговую валидацию перед созданием.
