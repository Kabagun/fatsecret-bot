# fatsecret-bot

Telegram-бот для групп пользователей: синхронизирует рецепты между несколькими FatSecret аккаунтами.

## MCP для чата

Приватный MCP повторяет операции с рецептами и продуктами через тот же движок, что использует бот.
Сервер привязан к **одной существующей группе** в настройках. Клиент не выбирает группу или аккаунты;
пароли, сессии FatSecret, Telegram ID и приглашения в группу не выдаются инструментами.
Аккаунты подключаются и отключаются в Telegram-боте.

Доступны:

- свежий список и поиск рецептов, все версии по аккаунтам, состав, шаги и текстовый экспорт;
- создание и изменение рецепта: ингредиенты, масса, порции, шаги, готовый вес;
- переименование, применение выбранной версии ко всем аккаунтам и удаление одного или нескольких рецептов;
- поиск продуктов по всем аккаунтам группы, поиск брендов и проверка штрих-кода;
- создание личного продукта с КБЖУ на 100 г или порцию, брендом и штрих-кодом;
- сохранённые черновики, продолжение после переподключения, отмена и повтор того же действия после сбоя.

### Сценарий создания рецепта

1. Чат вызывает `prepare_recipe` с названием и списком ингредиентов в граммах.
2. Для каждой новой строки сервер возвращает варианты с названием, брендом и КБЖУ. Чат показывает их
   пользователю и применяет выбранный вариант через `set_recipe_ingredient`.
3. Если подходящего продукта нет, чат уточняет КБЖУ с этикетки. `prepare_custom_food` получает ссылки
   на черновик и строку ингредиента и возвращает предпросмотр продукта.
4. После подтверждения пользователя `confirm_action` создаёт и проверяет личный продукт на аккаунтах
   группы и **сам вставляет его в рецепт**. Разные FatSecret ID остаются внутри сервера.
5. Чат показывает итоговый рецепт. После отдельного подтверждения `confirm_action` сохраняет его
   во всех аккаунтах. Неразрешённые ингредиенты и устаревшая версия черновика блокируют запись.

Для изменения существующего рецепта сначала используются `list_recipes` и `get_recipe`, затем
`prepare_recipe(source_variant_ref=...)`. Пропущенные поля сохраняются. Если версии различаются,
чат предлагает выбрать источник. Движок проверяет исходную версию перед записью.
Переименование, синхронизация и удаление готовятся через `prepare_recipe_action`, затем подтверждаются.
Подтверждение относится к точному предпросмотру и его `revision`; после изменения черновика нужно новое.

Ссылки `recipe_ref`, `candidate_ref`, `ingredient_ref` и другие — непрозрачные указатели для инструментов.
Пользователь их не вводит. Они доступны только настроенной группе и живут семь дней;
`list_drafts` и `get_action` восстанавливают сохранённый сценарий.
КБЖУ не угадываются. Для добавления продукта с питательностью на порцию в рецепт нужен вес этой порции.
Известный штрих-код возвращает существующий продукт вместо создания дубликата.

### Подключение и OAuth

Установить обновлённые зависимости в окружение проекта (`pip install -e .` либо `pip install -r requirements.txt`).
В `.env` задать:

```dotenv
FATSECRET_MCP_ENABLED=true
FATSECRET_MCP_GROUP_ID=<UUID существующей группы из runtime SQLite>
FATSECRET_MCP_GROUP_KEY=<отдельный случайный ключ длиной от 32 символов>
FATSECRET_MCP_ISSUER_URL=https://fatsecret.example.test
FATSECRET_MCP_HOST=127.0.0.1
FATSECRET_MCP_PORT=8765
```

Домен в примере — заполнитель: нужен реальный HTTPS-домен сервера.
Случайный ключ можно сгенерировать локально командой `python -c "import secrets; print(secrets.token_urlsafe(48))"`.
UUID группы задаётся один раз администратором; его можно получить командой `fatsecret-mcp --list-groups`.
Не помещать реальные значения, базу или ключ в Git.

При обычном запуске бота включённый MCP поднимается рядом с ним в том же процессе.
HTTPS-прокси должен передавать на этот порт `/mcp`, `/.well-known/*`, `/register`, `/authorize`,
`/consent`, `/token` и `/revoke`, сохранять исходный `Host` и поддерживать POST и потоковые ответы.
Origin задаётся без префикса пути. Проверка Host включена; отключать её для прокси не требуется.
По умолчанию MCP выключен, порт привязан к loopback.

В MCP-клиенте добавить URL `https://<ваш-домен>/mcp`, транспорт **Streamable HTTP** и OAuth.
Обнаружение OAuth и регистрация клиента выполняются автоматически. На странице подключения ввести
ключ группы и разрешить доступ. Он предоставляет чтение и изменение всей выбранной группы.
Это отдельный доступ к боту, а не повторная авторизация каждого FatSecret аккаунта.
Поддерживаются PKCE S256, одноразовые коды, обновление и отзыв токенов; коды и токены в SQLite
хранятся в виде хешей. Изменение ключа подключения аннулирует ранее выданные учётные данные MCP.
Для внешнего подключения обязателен HTTPS; HTTP разрешён только на localhost.

Для площадок, где веб-доступ выделяется отдельному приложению, есть декларация
`deploy/fatsecret-mcp.yaml` и файл запуска `run`. Такой шлюз использует выделенные площадкой `HOST`/`PORT`
и передаёт запросы локальному MCP бота (`FATSECRET_MCP_UPSTREAM`, по умолчанию `http://127.0.0.1:8765`).
Ему не нужны база, пароли или ключ группы. Он сохраняет заголовки OAuth, cookies и потоковые ответы;
авторизация и операции выполняются в процессе бота. Зависимости шлюза устанавливаются в
`temp/mcp-gateway-venv`, а `FATSECRET_MCP_ISSUER_URL` бота указывает на публичный origin шлюза.

Отдельный процесс для разработки или локального клиента:

```powershell
fatsecret-mcp
fatsecret-mcp --transport stdio
```

Эти режимы используют те же настройки группы и базы и не требуют Telegram-токена.
При запуске через модуль: `python -m fatsecret_bot.mcp_server` с теми же аргументами.
В stdio доступ разрешён владельцу локального процесса; OAuth используется для HTTP.
Не запускать отдельный MCP одновременно с ботом на одной базе: блокировка процесса отклонит второй запуск.
Для совместной работы использовать встроенный HTTP-сервер; его операции и операции бота
выполняются последовательно, с сохранением проверки версии и журналов восстановления.

Проверки MCP: `python -m pytest tests/test_mcp_*.py -q`.
Они используют синтетические группы и аккаунты, не выполняя действий в реальном FatSecret.

## Что уже реализовано

- Telegram-пользователи:
  - любой пользователь Telegram регистрируется при первом обращении к боту;
  - рецепты, FatSecret-аккаунты и синхронизация изолированы активной группой.
- Группы рецептов:
  - пользователь создает группу или подключается по коду;
  - обычный пользователь может состоять только в одной группе; дополнительными группами и переключением управляет только Telegram-администратор из `TELEGRAM_ADMIN_USER_ID`;
  - при смене активной группы все FatSecret-аккаунты, которыми владеет пользователь, автоматически переходят вместе с ним; аккаунты других участников остаются на месте;
  - создатель группы может переименовать группу;
  - группа ограничивает список рецептов, аккаунтов и синхронизацию.
- Один Telegram-пользователь может добавить несколько FatSecret аккаунтов через кнопку `🔗 Аккаунты FatSecret`; логин/пароль проверяются перед сохранением, затем задаётся короткий ник.
- Один FatSecret аккаунт прикрепляется не более чем к одной группе. При выходе из последней группы принадлежащие пользователю аккаунты сохраняются вместе с credentials и сессиями, но остаются без группы. `↪️ Убрать из группы` делает то же для выбранного аккаунта, а `🗑️ Удалить из бота` удаляет credentials глобально из бота.
- Импорт cookbook только в активную группу и merge по нормализованному названию рецепта внутри этой группы.
- Просмотр общего списка `/recipes`.
- Поиск внутри списка рецептов.
- Обновление из FatSecret `/refresh`.
- Просмотр account-specific версий рецепта; одинаковые версии объединяются, конфликтующие показываются одновременно с подписями аккаунтов.
- Синхронизация выбранного рецепта из выбранного FatSecret аккаунта во все подключенные аккаунты.
- Изменение порций, ингредиентов, их массы и шагов из карточки рецепта с предпросмотром и явным подтверждением.
- Создание рецепта из списка строк вида `название масса_г` с предварительной валидацией ингредиентов.
- Создание личного продукта во всех FatSecret аккаунтах активной группы через мастер: название, необязательные штрих-код и бренд, выбор КБЖУ на 100 г или на 1 порцию.
- Распознавание EAN/UPC с фотографии штрих-кода или ввод цифр вручную; перед созданием бот проверяет существующую привязку FatSecret.
- Создание отсутствующего продукта прямо из неразрешенной строки рецепта с account-specific ID для каждого аккаунта группы.
- Удаление рецепта из FatSecret на всех привязанных аккаунтах.
- Batch-удаление нескольких рецептов из FatSecret.

Рецепт можно создать из валидированного текстового списка либо создать/изменить в FatSecret и затем явно синхронизировать выбранную account-specific версию.

Подключение дополнительного аккаунта загружает его cookbook в активную группу. Отсутствующие рецепты не создаются автоматически; перенос происходит после явного создания из списка или кнопки `🔄 Применить эту версию везде`.

## Важное ограничение MVP

Создание рецепта на втором аккаунте подтверждено live-capture: `RecipeActionAndroidPage.aspx` с `action=recipeinitialsave`, `prid=0`; ответ имеет формат `SUCCESS:<recipe_id>`. Затем бот переносит ингредиенты через `ingredientsave` и сохраняет метаданные через `recipesave`.

Создание и замена из текстового списка используют отдельный журнал SQLite. До первого remote-write бот сохраняет payload, новый локальный UUID, исходные и новые remote ID и этап для каждого аккаунта. Старые remote-рецепты удаляются только после точного readback нового рецепта во всех аккаунтах; локальный рецепт и mappings публикуются одной транзакцией. Повтор того же запроса продолжает сохранённый этап и не создаёт второй remote-рецепт. При замене сохраняется существующий локальный recipe ID, а каждому новому ingredient row назначается свежий UUID.

Синхронизация делает целевой рецепт точной копией источника. Из-за stale detail официального приложения изменившийся существующий target заменяется durable create-and-swap: бот создаёт временный рецепт, полностью заполняет и проверяет его, удаляет старый target, переименовывает новый и атомарно меняет mapping. Неизменившийся target не пересоздаётся. Прогресс swap хранится в SQLite и может быть продолжен после сбоя на финальном rename.

Личные продукты определяются серверным custom-food endpoint, заранее клонируются через `saveregional`, проверяются на видимость target-аккаунту и получают двусторонний account-specific mapping. Публичный продукт остаётся с общим ID. Если FatSecret не принимает изменение или authoritative readback не совпадает с ожидаемым fingerprint, аккаунт получает `ERROR`, а не неполный `OK`.

Ручное создание продукта использует тот же `saveregional`, но сначала сохраняет durable-журнал для всех аккаунтов группы. Каждый remote ID подтверждается точным readback; повтор после timeout продолжает журнал и не отправляет мутацию вслепую. Мастер создаёт продукт со значениями на 100 г или на 1 порцию и позволяет отдельно указать или пропустить штрих-код и бренд. Для порции сохраняются её название и известный вес; отсутствие веса не подменяется 100 граммами. `Per100g` отправляется как официальный Android-контракт: без отдельного имени порции `servingSize` и с локализованным `metricServingSize` (`100г` для русского аккаунта), поэтому FatSecret показывает одну обычную порцию в граммах. Перед подтверждением бот проверяет грубые противоречия КБЖУ по формуле `4×белки + 9×жиры + 4×углеводы`, оставляя запас для округления этикетки, клетчатки и сахарных спиртов. Для непустого бренда бот загружает locale-specific каталог производителей из официального Android endpoint, предлагает канонические совпадения и оставляет явный выбор свободного текста; выбранное название отправляется как FatSecret manufacturer type `Brand`. При пропуске поля бренда не отправляются. Штрих-код прикрепляется к одному детерминированному аккаунту, потому что его серверная привязка общая, а account-specific продукты на остальных аккаунтах связываются локальным mapping.

Фото штрих-кода обрабатывается в памяти: бот распознаёт один EAN-8, UPC-A, EAN-13 или GTIN-14, проверяет контрольную цифру и вызывает app endpoint barcode lookup. Если FatSecret уже знает код в черновике рецепта, найденный продукт подставляется без создания дубликата. Принятый `saveregional` штрих-код может появиться в поисковом barcode index не сразу, поэтому успешное создание подтверждается readback самого продукта, а не немедленной выдачей scan endpoint.

Поля ингредиента из ответа FatSecret (`rid`, `portionid`, `portionamount`) используются для межаккаунтной синхронизации без пересчёта. Нормализация в граммы существует отдельно только для отображения в Telegram и локального поиска. Source `iid` никогда не переносится: для добавления используется `iid=0`, а для обновления — `iid` строки целевого рецепта. Exact-sync не подменяет отклонённый публичный продукт похожим результатом поиска; исключение — подтверждённый `isOwn=true` продукт, для которого создаётся account-specific копия. Обычная синхронизация не перезаписывает аккаунт-источник и не меняет дату, но создание, ручное изменение и переименование рецепта обновляют единственную служебную строку `Последняя синхронизация: ...`, сохраняя пользовательский текст и служебную строку готового веса.

Удаление рецепта использует `RecipeActionAndroidPage.aspx` с `action=recipedelete`, `rid=<recipe id>`, `fl=5`. После timeout/5xx бот читает cookbook: исчезнувший ID считается удалённым, оставшийся получает один повтор и финальный readback, а при недоступном cookbook mapping сохраняется как неопределённый.

Каждый Android/app запрос с auth-ошибкой или redirect получает не более одного повтора после fresh login. Безопасные cookbook/detail/custom-food чтения дополнительно получают до трёх попыток на timeout/429/502/503/504. Мутации транспортно не повторяются: после неоднозначного timeout бот сначала читает фактическое состояние и строит новый diff. Если новый target не прошёл проверку, бот удаляет его; старый target rollback не затрагивает.

Полностью загруженный cookbook всех аккаунтов считается источником истины для remote-привязок и account-specific snapshots. Перед каждым фактическим созданием из списка, включая copy/replace, бот повторно загружает все cookbook; ошибка одного аккаунта отменяет создание и reconciliation.

## Установка

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполнить `.env`:

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_ADMIN_USER_ID` — Telegram ID администратора, которому доступны дополнительные группы и переключение между ними
- при необходимости `FATSECRET_AUTHORIZATION` и `FATSECRET_C_DESC`

FatSecret логины/пароли вводятся в боте через `Аккаунты` и сохраняются в runtime SQLite. `.env` и runtime SQLite лежат вне git. На Linux бот создаёт и исправляет права файла SQLite на `0600`; каталог данных также должен быть доступен только пользователю сервиса.

SQLite намеренно используется одним синхронным соединением в последовательном event loop Telegram-бота. Методы Storage завершают транзакцию до возврата; `concurrent_updates` отключён явно, а ожидание занятой базы ограничено пятью секундами.

Подробная безопасная трассировка запросов и синхронизации пишется в `FATSECRET_BOT_LOG_PATH` (по умолчанию рядом с SQLite в `fatsecret_bot.log`). Файл ротируется ежедневно, а архивы старше `FATSECRET_BOT_LOG_RETENTION_DAYS` удаляются; значение по умолчанию — 10 дней. Лог содержит аккаунт, action, recipe/food/ingredient/portion ids, выбранные fallback-кандидаты, HTTP status/Location и rollback, но не содержит пароли, auth headers или session keys.

## Запуск

```powershell
.\.venv\Scripts\Activate.ps1
python run_bot.py
```

Или после установки пакета в editable-режиме:

```powershell
pip install -e .
fatsecret-bot
```

## Команды

- `/start` - зарегистрироваться/проверить доступ.
- `/refresh` - подтянуть cookbook из FatSecret аккаунтов активной группы и смержить список.
- `/recipes` - показать объединенный список рецептов.
- `/groups` - создать/подключить группу, переключить активную или отключиться от текущей.

В карточке рецепта есть кнопки:

- `✏️ Изменить рецепт`
- `📤 Экспортировать рецепт`
- `🔄 Применить эту версию везде` — только когда версии различаются
- `🏷️ Изменить название`
- `🗑️ Удалить рецепт`
- `⬅️ Все рецепты`

Экран изменения показывает копируемый блок в том же формате, что импорт. Бот сначала разбирает отправленный текст и показывает черновик. Запись в FatSecret начинается только после `✅ Сохранить изменения`.

Переименование проверяет свежий cookbook всех аккаунтов. Если имя уже занято, бот предлагает
обновить существующий рецепт, выбрать свободное имя с числовым суффиксом (`Название 2`, `Название 3`, ...)
или отменить действие. При обновлении выбранный рецепт сначала переименовывается и проверяется во всех
аккаунтах; прежний одноимённый рецепт удаляется только после успешной проверки.

После `/start` бот показывает постоянные кнопки:

- `🍽️ Все рецепты`
- `➕ Новый рецепт`
- `🥕 Новый продукт`
- `👥 Моя группа` (у администратора — `👥 Группы`)
- `🔗 Аккаунты FatSecret`

В списке рецептов есть пагинация, поиск по уже загруженному кэшу, подпись аккаунтов-владельцев и `🗑️ Удалить несколько`. После 10 минут бот показывает `🔄 Обновить список`.
Если версии одного рецепта различаются только метаданными, экран сравнения показывает лишь отличающиеся поля по аккаунтам.
Например, при `19` и `20` порциях ингредиенты и шаги больше не выводятся дважды.

В открытой карточке рецепта кнопки идут в порядке: `Изменить название`, `Изменить рецепт`, `Синхронизировать`, `Удалить рецепт`, `Экспортировать`, `Все рецепты`. Синхронизация доступна, если версии различаются или рецепт отсутствует хотя бы в одном подключённом аккаунте группы. Если во всех аккаунтах рецепт одинаковый, кнопка скрыта. Сохранённый готовый вес отображается сразу после количества порций.

Формат создания из списка:

```text
Порций: 4
Филе 100
Теос греческий 200
Масло 6

Шаги:
Нарезать ингредиенты
Смешать и приготовить
```

Бот требует отдельную строку с количеством порций, считает последнее число в строке ингредиента граммами, подбирает продукты и показывает итоговую проверку перед созданием или сохранением. Шаги после `Шаги:` записываются отдельными строками без добавляемой ботом нумерации; старые блоки с номерами по-прежнему принимаются.

Если строка рецепта не найдена, рядом доступны `Найти`, `Создать` и `Удалить`. `Создать` запускает тот же мастер продукта; после успешного создания ингредиент автоматически возвращается в черновик с правильным remote food ID для каждого FatSecret аккаунта группы.

До создания рецепта можно изменить количество порций и массу каждого ингредиента прямо в черновике. Отдельно можно задать готовый вес блюда. Изменение количества порций делит прежнее общее КБЖУ на новое число порций; изменение массы ингредиента пересчитывает его вклад в КБЖУ. Отмена создания отвечает `Создание рецепта отменено.`

При создании продукта доступны только `На 100 г` и `На 1 порцию`. Например, для продукта `Блин` можно ввести КБЖУ одного блина, а затем учитывать целые и дробные порции. Для пересчёта между порциями и граммами мастер предлагает указать вес одной порции. При самостоятельном создании продукта этот вес можно пропустить; при создании ингредиента из рецепта он обязателен, поскольку список ингредиентов задаётся в граммах. Миллилитры, ложки и другие единицы в мастере не предлагаются.
