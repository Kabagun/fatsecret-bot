# fatsecret-bot

Telegram-бот для групп пользователей: синхронизирует рецепты между несколькими FatSecret аккаунтами и копирует заполненный дневник питания в выбранные аккаунты и диапазон дат.

## Что уже реализовано

- Telegram-пользователи:
  - любой пользователь Telegram регистрируется при первом обращении к боту;
  - рецепты, FatSecret-аккаунты и синхронизация изолированы активной группой.
- Группы рецептов:
  - пользователь создает группу или подключается по коду;
  - обычный пользователь может состоять только в одной группе; дополнительными группами и переключением управляет только Telegram-администратор из `TELEGRAM_ADMIN_USER_ID`;
  - при смене активной группы все FatSecret-аккаунты, которыми владеет пользователь, автоматически переходят вместе с ним; аккаунты других участников остаются на месте;
  - создатель группы может переименовать группу;
  - группа ограничивает список рецептов, аккаунтов и синхронизацию.
- Один Telegram-пользователь может добавить несколько FatSecret аккаунтов через кнопку `Аккаунты`; логин/пароль проверяются перед сохранением, затем задаётся короткий ник.
- Один FatSecret аккаунт прикрепляется не более чем к одной группе. При выходе из последней группы принадлежащие пользователю аккаунты сохраняются вместе с credentials и сессиями, но остаются без группы. `Отсоединить` делает то же для выбранного аккаунта, а `Удалить подключение` удаляет credentials глобально из бота.
- Импорт cookbook только в активную группу и merge по нормализованному названию рецепта внутри этой группы.
- Просмотр общего списка `/recipes`.
- Поиск внутри списка рецептов.
- Обновление из FatSecret `/refresh`.
- Просмотр account-specific версий рецепта; одинаковые версии объединяются, конфликтующие показываются одновременно с подписями аккаунтов.
- Синхронизация выбранного рецепта из выбранного FatSecret аккаунта во все подключенные аккаунты.
- Создание рецепта из списка строк вида `название масса_г` с предварительной валидацией ингредиентов.
- Создание личного продукта во всех FatSecret аккаунтах активной группы через короткий мастер: название, необязательный штрих-код и КБЖУ на 100 г.
- Распознавание EAN/UPC с фотографии штрих-кода или ввод цифр вручную; перед созданием бот проверяет существующую привязку FatSecret.
- Создание отсутствующего продукта прямо из неразрешенной строки рецепта с account-specific ID для каждого аккаунта группы.
- Удаление рецепта из FatSecret на всех привязанных аккаунтах.
- Batch-удаление нескольких рецептов из FatSecret.
- Копирование всего дневника еды с выбранного аккаунта и даты в один или несколько отмеченных аккаунтов группы:
  - временно доступно только Telegram-администратору из `TELEGRAM_ADMIN_USER_ID`;
  - произвольный диапазон от 1 до 7 дней;
  - существующая еда не удаляется, новые записи добавляются;
  - исходная дата на исходном аккаунте автоматически исключается;
  - личные рецепты синхронизируются через recipe mappings;
  - личные продукты один раз клонируются в каждый target-аккаунт и переиспользуются;
  - повтор одного и того же callback не добавляет еду второй раз;
  - прерванная операция может быть продолжена после 30 минут без heartbeat.

Рецепт можно создать из валидированного текстового списка либо создать/изменить в FatSecret и затем явно синхронизировать выбранную account-specific версию.

Подключение дополнительного аккаунта загружает его cookbook в активную группу. Отсутствующие рецепты не создаются автоматически; перенос происходит после явного создания из списка или кнопки `Синхронизировать`.

## Важное ограничение MVP

Создание рецепта на втором аккаунте подтверждено live-capture: `RecipeActionAndroidPage.aspx` с `action=recipeinitialsave`, `prid=0`; ответ имеет формат `SUCCESS:<recipe_id>`. Затем бот переносит ингредиенты через `ingredientsave` и сохраняет метаданные через `recipesave`.

Создание и замена из текстового списка используют отдельный журнал SQLite. До первого remote-write бот сохраняет payload, новый локальный UUID, исходные и новые remote ID и этап для каждого аккаунта. Старые remote-рецепты удаляются только после точного readback нового рецепта во всех аккаунтах; локальный рецепт и mappings публикуются одной транзакцией. Повтор того же запроса продолжает сохранённый этап и не создаёт второй remote-рецепт. При замене сохраняется существующий локальный recipe ID, а каждому новому ingredient row назначается свежий UUID.

Синхронизация делает целевой рецепт точной копией источника. Из-за stale detail официального приложения изменившийся существующий target заменяется durable create-and-swap: бот создаёт временный рецепт, полностью заполняет и проверяет его, удаляет старый target, переименовывает новый и атомарно меняет mapping. Неизменившийся target не пересоздаётся. Прогресс swap хранится в SQLite и может быть продолжен после сбоя на финальном rename.

Личные продукты определяются серверным custom-food endpoint, заранее клонируются через `saveregional`, проверяются на видимость target-аккаунту и получают двусторонний account-specific mapping. Публичный продукт остаётся с общим ID. Если FatSecret не принимает изменение или authoritative readback не совпадает с ожидаемым fingerprint, аккаунт получает `ERROR`, а не неполный `OK`.

Ручное создание продукта использует тот же `saveregional`, но сначала сохраняет durable-журнал для всех аккаунтов группы. Каждый remote ID подтверждается точным readback; повтор после timeout продолжает журнал и не отправляет мутацию вслепую. Мастер создаёт простой продукт со значениями на 100 г и позволяет отдельно указать или пропустить штрих-код и бренд. `Per100g` отправляется как официальный Android-контракт: без отдельного имени порции `servingSize` и с локализованным `metricServingSize` (`100г` для русского аккаунта), поэтому FatSecret показывает одну обычную порцию в граммах. Перед подтверждением бот проверяет грубые противоречия КБЖУ по формуле `4×белки + 9×жиры + 4×углеводы`, оставляя запас для округления этикетки, клетчатки и сахарных спиртов. Для непустого бренда бот загружает locale-specific каталог производителей из официального Android endpoint, предлагает канонические совпадения и оставляет явный выбор свободного текста; выбранное название отправляется как FatSecret manufacturer type `Brand`. При пропуске поля бренда не отправляются. Штрих-код прикрепляется к одному детерминированному аккаунту, потому что его серверная привязка общая, а account-specific продукты на остальных аккаунтах связываются локальным mapping.

Фото штрих-кода обрабатывается в памяти: бот распознаёт один EAN-8, UPC-A, EAN-13 или GTIN-14, проверяет контрольную цифру и вызывает app endpoint barcode lookup. Если FatSecret уже знает код в черновике рецепта, найденный продукт подставляется без создания дубликата. Принятый `saveregional` штрих-код может появиться в поисковом barcode index не сразу, поэтому успешное создание подтверждается readback самого продукта, а не немедленной выдачей scan endpoint.

Поля ингредиента из ответа FatSecret (`rid`, `portionid`, `portionamount`) используются для межаккаунтной синхронизации без пересчёта. Нормализация в граммы существует отдельно только для отображения в Telegram и локального поиска. Source `iid` никогда не переносится: для добавления используется `iid=0`, а для обновления — `iid` строки целевого рецепта. Exact-sync не подменяет отклонённый публичный продукт похожим результатом поиска; исключение — подтверждённый `isOwn=true` продукт, для которого создаётся account-specific копия. Аккаунт-источник синхронизация не перезаписывает, а пользовательское описание переносится без служебного timestamp поверх него.

Удаление рецепта использует `RecipeActionAndroidPage.aspx` с `action=recipedelete`, `rid=<recipe id>`, `fl=5`. После timeout/5xx бот читает cookbook: исчезнувший ID считается удалённым, оставшийся получает один повтор и финальный readback, а при недоступном cookbook mapping сохраняется как неопределённый.

Каждый Android/app запрос с auth-ошибкой или redirect получает не более одного повтора после fresh login. Безопасные cookbook/detail/custom-food чтения дополнительно получают до трёх попыток на timeout/429/502/503/504. Мутации транспортно не повторяются: после неоднозначного timeout бот сначала читает фактическое состояние и строит новый diff. Если новый target не прошёл проверку, бот удаляет его; старый target rollback не затрагивает.

Полностью загруженный cookbook всех аккаунтов считается источником истины для remote-привязок и account-specific snapshots. Перед каждым фактическим созданием из списка, включая copy/replace, бот повторно загружает все cookbook; ошибка одного аккаунта отменяет создание и reconciliation.

Для дневника используются Android-контракты `RecipeJournalDayAndroidPage.aspx` и `update-journal-entries`. Личные продукты читаются через `RecipeAndroidPage.aspx` и создаются на втором аккаунте через `RecipeCustomEntryActionAndroidPage.aspx` с `action=saveregional`. Общий для дневника и рецептов mapping хранится в SQLite, поэтому один и тот же продукт повторно не создаётся.

Копирование переносит только записи еды. Вода, упражнения, фотографии и заметки не копируются. Перед записью бот показывает источник, диапазон, количество строк и предупреждает, что существующие записи сохранятся.

## Установка

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

Заполнить `.env`:

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_ADMIN_USER_ID` — Telegram ID администратора, которому доступны дополнительные группы, переключение между ними и копирование дневника
- при необходимости `FATSECRET_AUTHORIZATION` и `FATSECRET_C_DESC`

FatSecret логины/пароли вводятся в боте через `Аккаунты` и сохраняются в runtime SQLite. `.env` и runtime SQLite лежат вне git. На Linux бот создаёт и исправляет права файла SQLite на `0600`; каталог данных также должен быть доступен только пользователю сервиса.

SQLite намеренно используется одним синхронным соединением в последовательном event loop Telegram-бота. Методы Storage завершают транзакцию до возврата; `concurrent_updates` отключён явно, а ожидание занятой базы ограничено пятью секундами.

Подробная безопасная трассировка запросов и синхронизации пишется в `FATSECRET_BOT_LOG_PATH` (по умолчанию рядом с SQLite в `fatsecret_bot.log`). Файл ротируется ежедневно, а архивы старше `FATSECRET_BOT_LOG_RETENTION_DAYS` удаляются; значение по умолчанию — 10 дней. Лог содержит аккаунт, action, recipe/food/ingredient/portion ids, выбранные fallback-кандидаты, HTTP status/Location и rollback, но не содержит пароли, auth headers или session keys.

## Запуск

```powershell
.\.venv\Scripts\Activate.ps1
python run_bot.py
```

Или после установки пакета в editable-режиме:

```powershell
pip install -e .
fatsecret-bot
```

## Команды

- `/start` - зарегистрироваться/проверить доступ.
- `/refresh` - подтянуть cookbook из FatSecret аккаунтов активной группы и смержить список.
- `/recipes` - показать объединенный список рецептов.
- `/groups` - создать/подключить группу, переключить активную или отключиться от текущей.
- `/diary` - выбрать аккаунт-источник, один или несколько targets, исходную дату и диапазон копирования.

В карточке рецепта есть кнопки:

- `Синхронизировать`
- `Переименовать`
- `Удалить в FatSecret`
- `К списку`

Переименование проверяет свежий cookbook всех аккаунтов. Если имя уже занято, бот предлагает
обновить существующий рецепт, выбрать свободное имя с числовым суффиксом (`Название 2`, `Название 3`, ...)
или отменить действие. При обновлении выбранный рецепт сначала переименовывается и проверяется во всех
аккаунтах; прежний одноимённый рецепт удаляется только после успешной проверки.

После `/start` бот показывает постоянные кнопки:

- `Рецепты`
- `Создать продукт`
- `Меню / Дневник`
- `Аккаунты`
- `Группы`

В списке рецептов есть пагинация, поиск, создание из списка, подпись аккаунтов-владельцев и кнопка `Удалить несколько` для batch-удаления. Inline-кнопки `Обновить` в списке нет; обновление доступно через `/refresh`.
Если версии одного рецепта различаются только метаданными, экран сравнения показывает лишь отличающиеся поля по аккаунтам.
Например, при `19` и `20` порциях ингредиенты и шаги больше не выводятся дважды.

Формат создания из списка:

```text
Филе 100
Теос греческий 200
Масло 6
```

Бот считает последнее число граммами, подбирает часто использованные ингредиенты из рецептов группы, затем ищет в FatSecret и показывает итоговую валидацию перед созданием.

Если строка рецепта не найдена, рядом доступны `Найти`, `Создать` и `Удалить`. `Создать` запускает тот же мастер продукта; после успешного создания ингредиент автоматически возвращается в черновик с правильным remote food ID для каждого FatSecret аккаунта группы.
