# Ручная проверка рецептов FatSecret Bot

Этот чеклист проверяет пользовательские сценарии через Telegram-бот и два приложения FatSecret. Он не предназначен для искусственного вызова HTTP 302, порчи сессий или проверки аварийного rollback — эти ветки покрываются автоматическими тестами.

## Правила запуска

- Выполнять проверку в группе `QA`, где подключены аккаунт Kabaye (`Святичек`) и тестовый FatSecret-аккаунт.
- Kabaye может оставаться участником основной группы, но на время проверки его активной группой должна быть `QA`.
- Задать `RUN_ID` в формате `YYYYMMDD-HHMM`. Все созданные рецепты называть `QA-<RUN_ID>-<назначение>`.
- Не изменять и не удалять рецепты без текущего QA-префикса.
- Сохранять созданные рецепты до тестов удаления в конце чеклиста.
- После каждого создания или синхронизации дождаться результата по обоим аккаунтам и открыть рецепт в каждом приложении FatSecret.
- Один FatSecret-аккаунт Kabaye используется в двух группах, поэтому его временные QA-рецепты физически находятся в общем cookbook и могут быть видны из основной группы до финальной очистки.

## Как проверять валидность рецепта

Для каждого успешно созданного или синхронизированного рецепта проверить:

- [ ] название и отсутствие неожиданного цифрового суффикса;
- [ ] количество порций;
- [ ] описание, время подготовки, время приготовления и шаги, если они заданы;
- [ ] число ингредиентов — нет пропущенных и лишних строк;
- [ ] название и бренд каждого продукта после открытия его карточки;
- [ ] массу, единицу и количество порций каждого ингредиента;
- [ ] отсутствие умножения граммов на 100;
- [ ] питание на порцию совпадает между аккаунтами с учётом округления FatSecret;
- [ ] source-рецепт не изменился после синхронизации из него.

Разница до 1 ккал и до 0,2 г по Б/Ж/У допустима только как округление интерфейса. Отличающийся продукт, бренд, масса или количество ингредиентов — это `FAIL`.

## TC-01. Проверка некорректного ввода

### Шаги

1. Нажать `Создать из списка` и указать имя `QA-<RUN_ID>-INVALID`.
2. Отправить список без количества порций:

   ```text
   Яйцо 100
   ```

3. Убедиться, что бот требует строку `Порций:` и ничего не создаёт.
4. Начать заново с тем же именем и отправить:

   ```text
   Порций: 2
   Яйцо сто
   Масло 0
   ```

5. Нажать `Отмена`.

### Ожидаемый результат

- [ ] Бот показывает ошибочные строки и правильный формат.
- [ ] Кнопка создания валидного рецепта не появляется.
- [ ] В боте и обоих FatSecret cookbook нет `QA-<RUN_ID>-INVALID`.

## TC-02. Заполнение и удаление неизвестных ингредиентов

### Данные

Имя: `QA-<RUN_ID>-RESOLVE`

```text
Порций: 2
Яйцо 100
НесуществующийПродуктАльфа 50
НесуществующийПродуктБета 10
Соль 2

Шаги:
1. Смешать
2. Приготовить
```

### Шаги

1. Создать черновик из данных выше.
2. Убедиться, что неизвестные позиции вынесены в отдельный блок и создание заблокировано.
3. Для `НесуществующийПродуктАльфа` нажать `Заполнить`, найти `Лук Репчатый` и выбрать его.
4. Для `НесуществующийПродуктБета` нажать `Удалить`.
5. Проверить итоговый экран и создать рецепт.

### Ожидаемый результат

- [ ] До разрешения всех строк кнопка `Создать рецепт` недоступна.
- [ ] В итоговом рецепте есть яйцо 100 г, выбранный лук 50 г и соль 2 г.
- [ ] Строки `НесуществующийПродуктАльфа/Бета` не сохранились как продукты.
- [ ] Рецепт создан в обоих аккаунтах.

## TC-03. Изменение имени и шагов

1. В процессе TC-02 нажать `Изменить имя` и задать `QA-<RUN_ID>-RESOLVE-RENAMED`.
2. Нажать `Изменить шаги` и отправить:

   ```text
   Подготовить ингредиенты
   Смешать
   Приготовить до готовности
   ```

3. Создать рецепт и открыть его в обоих приложениях.
4. Повторить изменение шагов в новом черновике и отправить `-`, чтобы проверить очистку шагов; затем отменить этот черновик.

### Ожидаемый результат

- [ ] Сохранено новое имя без старого варианта.
- [ ] В FatSecret присутствуют ровно три шага в заданном порядке.
- [ ] Отправка `-` очищает шаги в черновике.
- [ ] Отмена не создаёт дополнительный рецепт.

## TC-04. Выбранный продукт «Бекон Мираторг»

### Данные

Имя: `QA-<RUN_ID>-OMELET`

```text
Порций: 4
Яйцо 236
Помидоры 140
Молоко 2.5% 160
Бекон 80

Шаги:
1. Нарезать помидоры и бекон
2. Смешать с яйцом и молоком
3. Приготовить омлет
```

### Шаги

1. Получить итоговый черновик.
2. Для строки `Бекон` нажать `Заменить`.
3. Отправить запрос `Бекон Мираторг`.
4. Выбрать вариант, в кнопке и описании которого явно указан бренд `Мираторг`.
5. Сделать скриншот итогового окна с `Бекон (Мираторг)` и массой 80 г.
6. Создать рецепт.
7. Открыть ингредиент бекона внутри каждого приложения FatSecret и проверить производителя/бренд.

### Ожидаемый результат

- [ ] Создание завершилось `OK` для обоих аккаунтов.
- [ ] В обоих рецептах сохранено 80 г бекона.
- [ ] Открытая карточка продукта показывает `Мираторг`.
- [ ] Общий безбрендовый `Бекон` не подставлен.
- [ ] Остальные ингредиенты и шаги соответствуют черновику.

## TC-08. Настоящий дубликат: копия и замена

### Часть A — исходный рецепт

Создать `QA-<RUN_ID>-DUPLICATE`:

```text
Порций: 1
Яйцо 100
```

### Часть B — копия

1. Снова создать рецепт с именем `QA-<RUN_ID>-DUPLICATE`, но с `Помидоры 100`.
2. На экране дубликата выбрать `Создать копию`.

Ожидается:

- [ ] исходный рецепт сохранился с яйцом;
- [ ] копия получила следующий свободный цифровой суффикс;
- [ ] копия содержит помидоры, а не яйцо;
- [ ] оба рецепта есть в обоих аккаунтах.

### Часть C — обновление существующего

1. В третий раз создать `QA-<RUN_ID>-DUPLICATE` с `Лук Репчатый 50`.
2. Выбрать `Обновить существующий`.
3. Сохранить сообщение бота с временным именем, удалением старого и переименованием нового.

Ожидается:

- [ ] базовое имя осталось без суффикса;
- [ ] базовый рецепт теперь содержит только выбранный лук 50 г;
- [ ] старая версия с яйцом удалена;
- [ ] цифровая копия с помидорами не изменилась;
- [ ] временное имя не осталось в cookbook.

## TC-09. Внешнее удаление и stale duplicate

1. Создать `QA-<RUN_ID>-STALE` с одной строкой `Вода 100`.
2. Убедиться, что рецепт виден в обоих аккаунтах.
3. Удалить его вручную через приложение FatSecret в обоих аккаунтах, не используя бот.
4. Выполнить `/refresh` в активной группе `QA`.
5. Создать из списка новый рецепт с тем же именем и `Вода 150`.

### Ожидаемый результат

- [ ] Бот не показывает ложный duplicate prompt.
- [ ] Имя не получает суффикс `2` или `3`.
- [ ] Новый рецепт создан как `QA-<RUN_ID>-STALE` с водой 150 г в обоих аккаунтах.

## TC-10. Exact-sync существующего target из Kabaye

Создать вручную в приложении FatSecret одноимённый рецепт `QA-<RUN_ID>-EXACT-SYNC` в обоих аккаунтах.

### Kabaye — правильный source

- Порций: 3.
- Подготовка: 11 минут.
- Приготовление: 22 минуты.
- Описание: `QA source Kabaye <RUN_ID>`.
- Шаги: `Подготовить`, `Смешать`, `Приготовить`.
- Яйцо: 120 г.
- Йогурт Черника: 108 г.
- Молоко Савушкин 1.5%: 200 мл или штатная порция приложения.

### Тестовый target — намеренно неправильный

- Порций: 1.
- Подготовка: 1 минута.
- Приготовление: 2 минуты.
- Описание: `WRONG TARGET`.
- Яйцо: 60 г.
- Соль: 5 г — лишний ингредиент.
- Нет йогурта и молока.

### Шаги

1. Выполнить `/refresh`.
2. Открыть объединённую карточку рецепта и нажать `Синхронизировать`.
3. Выбрать источником Kabaye/`Святичек`.
4. Открыть рецепт в обоих приложениях.

### Ожидаемый результат

- [ ] Kabaye/source не изменился.
- [ ] Target получил порции, время, описание и шаги source.
- [ ] Яйцо обновлено до 120 г.
- [ ] Йогурт 108 г и молоко добавлены.
- [ ] Лишняя соль полностью удалена.
- [ ] В target нет других лишних ингредиентов.

## TC-11. Обратный exact-sync из тестового аккаунта

### Ожидаемый результат

- [ ] Kabaye стал точной отображаемой копией тестового source.
- [ ] Йогурт удалён из Kabaye.

## TC-12. Личный продукт Nina Farina

1. В аккаунте Kabaye вручную создать `QA-<RUN_ID>-CUSTOM-NINA`:
   - порций: 2;
   - `Сухая Смесь для Приготовления Мороженного Nina Farina`: 30 г;
   - вода: 100 г.
2. Убедиться, что точного рецепта нет в тестовом аккаунте.
3. Выполнить `/refresh` и синхронизировать из Kabaye.
4. В тестовом аккаунте открыть карточку созданного личного продукта и сравнить название, производителя, порцию и пищевую ценность.
5. В Kabaye изменить смесь с 30 г на 45 г и синхронизировать повторно.

### Ожидаемый результат

- [ ] Первый sync создал account-specific копию личного продукта в тестовом аккаунте.
- [ ] Название и производитель не заменены похожим общим продуктом.
- [ ] Пищевая ценность и размер порции совпадают с source.
- [ ] Второй sync использовал существующую копию и сохранил 45 г.
- [ ] В списке личных продуктов тестового аккаунта нет второй копии Nina Farina.

Личный custom food может остаться в тестовом аккаунте после удаления QA-рецептов: бот удаляет рецепты, но не удаляет созданные личные продукты.

## TC-14. Список, поиск и переключение групп

1. Выполнить `/refresh`, открыть `Рецепты` и найти каждый рецепт текущего RUN_ID через `Поиск рецептов`.
2. Проверить подписи владельцев и открытие карточек.
3. Проверить переход между страницами списка, не выбирая чужие рецепты для удаления.
4. Переключить Kabaye в основную группу, убедиться в названии активной группы, затем вернуться в `QA`.

### Ожидаемый результат

- [ ] Поиск находит QA-рецепты без дублей в списке.
- [ ] Владельцы отображаются корректно.
- [ ] После переключения активной группы действия выполняются только в выбранной группе.
- [ ] Возврат в `QA` восстанавливает доступ к тестовому аккаунту.

Не считать появление временного QA-рецепта в физическом cookbook Kabaye нарушением изоляции: один и тот же FatSecret-аккаунт используется в обеих группах. Все такие рецепты удаляются в TC-16.

## TC-15. Одиночное удаление

1. Выбрать `QA-<RUN_ID>-PUBLIC-MILK`.
2. Нажать `Удалить в FatSecret` и подтвердить.
3. Выполнить `/refresh`.

### Ожидаемый результат

- [ ] Бот сообщил `OK` по обоим привязанным аккаунтам.
- [ ] Рецепта нет в cookbook Kabaye.
- [ ] Рецепта нет в cookbook тестового аккаунта.
- [ ] Рецепт не возвращается в списке бота после `/refresh`.

## TC-16. Batch-удаление и финальная очистка

1. Открыть `Удалить несколько`.
2. Выбрать только рецепты с точным префиксом `QA-<RUN_ID>-`.
3. Проверить список на экране подтверждения.
4. Подтвердить batch-удаление.
5. Выполнить `/refresh` и поиск по `QA-<RUN_ID>`.
6. Проверить оба FatSecret cookbook.
7. Переключить Kabaye обратно в основную группу.

### Ожидаемый результат

- [ ] По каждому выбранному рецепту получен результат удаления.
- [ ] Ни один рецепт без текущего QA-префикса не удалён.
- [ ] Поиск в боте не находит рецепты текущего RUN_ID.
- [ ] В cookbook Kabaye нет рецептов текущего RUN_ID.
- [ ] В cookbook тестового аккаунта нет рецептов текущего RUN_ID.
- [ ] Исходное количество обычных рецептов не уменьшилось.

- [ ] новый target удаляется после ошибки ингредиентов или metadata;
