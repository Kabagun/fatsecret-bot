## TC-01 — Отмена во всех validation-ошибках

1. Начать `Создать из списка`, имя `QA-<RUN_ID>-INVALID`.
2. По очереди проверить отдельными попытками:
   - нет строки `Порций:`;
   - пустой список ингредиентов;
   - строки `Яйцо сто` и `Масло 0`;
   - ошибка подбора ингредиента (можно временно отключить сеть до отправки валидного списка).
3. В каждом ответе нажать `Отмена`.

Ожидается:

- [ ] В каждом validation-ответе видна кнопка `Отмена`.
- [ ] После отмены бот возвращает список рецептов и забывает draft.
- [ ] В cookbook всех аккаунтов нет `QA-<RUN_ID>-INVALID`.

## TC-10 — Exact-sync из `Святичек`

Создать одноимённый `QA-<RUN_ID>-EXACT-SYNC` в `Святичек` и `thekabaye`.

Source `Святичек`:

- 3 порции; подготовка 11 мин; готовка 22 мин;
- описание `QA source Svyat <RUN_ID>`;
- шаги `Подготовить`, `Смешать`, `Приготовить`;
- яйцо 120 г, йогурт черника 108 г, молоко Савушкин 1,5% 200 г/мл.

Неверный target `thekabaye`:

- 1 порция; времена 1/2 мин; описание `WRONG TARGET`;
- яйцо 60 г и лишняя соль 5 г; нет йогурта и молока.

1. Выполнить `/refresh`.
2. Открыть конфликт и убедиться, что бот показывает обе версии с правильными account labels.
3. Выбрать источником именно версию `Святичек` и синхронизировать один раз.
4. Снова открыть рецепт в боте и после полного перезапуска обоих приложений.

Ожидается:

- [ ] До sync обе версии видны одновременно и имеют отдельные кнопки открытия/source.
- [ ] Бот сообщает `OK` только после authoritative readback.
- [ ] Target получил новый remote ID после create-and-swap, старый ID исчез.
- [ ] Все metadata, шаги, продукты и массы совпадают; соль удалена.
- [ ] После refresh конфликт исчез и обе внешние карточки содержат одну версию.

## TC-MA — Несколько аккаунтов и групп

1. Один Telegram-пользователь открывает `Аккаунты` и добавляет минимум два собственных FatSecret-аккаунта.
2. Оба подключаются к активной группе `QA`; лимита `2/2` нет.
3. Telegram-пользователь создаёт или подключается ко второй группе и переключает активную группу без выхода из первой.
4. Отсоединить один свой FatSecret-аккаунт от `QA`, подключить его ко второй группе и попытаться повторно подключить к `QA`.
5. Проверить отдельно `Отсоединить` (credentials сохраняются) и `Удалить подключение` (глобальное удаление credentials владельцем).
6. В `Меню / Дневник` выбрать source и только один target из трёх аккаунтов; неподмеченный аккаунт не должен получить записи.

Ожидается:

- [ ] Один Telegram-пользователь владеет 2+ FatSecret-аккаунтами.
- [ ] Telegram-пользователь состоит в нескольких группах и свободно переключает активную.
- [ ] Один конкретный FatSecret-аккаунт одновременно прикреплён только к одной группе.
- [ ] Credentials/label меняет только владелец; создатель группы может только отсоединить аккаунт.
- [ ] Recipe sync обрабатывает все аккаунты активной группы.
- [ ] Diary copy пишет только в отмеченные target-аккаунты.
